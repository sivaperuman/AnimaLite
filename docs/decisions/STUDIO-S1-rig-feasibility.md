# S1 decision proposal · Character animation for Marvel Engineer

**Decision requested.** Use Godot’s headless two-bone solver and CPU vector rasterizer as the candidate for review. Keep the native analytic rig as the comparison. On this host Godot produced the same timed performance faster, with a higher sampled memory peak and a frame-sequence disk cost. An artist still needs to decide whether the walk, transfer and reaction are good enough to build on.

Neither has a demonstrated 9:16 recompose or production motion library. Godot and native playback deliberately use the same acting directions so reviewers can isolate renderer differences. The native clip preserves the SVG brick pattern on the building while the Godot capture shows the base fill. The figures, feet and paper remain legible in both. An editor usability comparison would require an artist editing the same shot.

The wall clock starts immediately before output setup and media-tool discovery. It includes binary/source hashing, rig evaluation, rasterization, any intermediate disk I/O, RGB hashing, encode and decode-count verification. It ends before final manifest writing, cleanup and rename. CPU seconds combine user and system time for the renderer process and its reaped children. The external observer sampled summed process-tree RSS approximately every 25 ms during the command. It includes native processes and can double count shared pages or miss a short spike. Raw samples, separate parent/child high-water marks, versioned settings, all 288 input-frame hashes and MP4 hashes are in the evidence bundle. Scratch counts are logical bytes of intermediate files observed before successful cleanup, excluding the output MP4, OS cache, libraries and installation.

Debian 13, Linux 6.18.57 x86-64, AMD EPYC 9V74, cgroup quota of four CPUs and 16 GiB RAM. Each run started a new Python 3.11.18 process. OS page cache was warm or uncontrolled. Both used local software rendering and FFmpeg 7.1.5 libx264 with one encoder thread. Godot used a dummy display, a single-threaded scene tree and a one-thread worker-pool setting. These settings describe the requested execution path. GPU utilization, network packets, energy, physical memory bandwidth and total concurrent native threads were not instrumented.

Both clips decoded as H.264 High, yuv420p, BT.709 matrix, TV range, 1280×720, 288 frames, 24/1 fps and 12.000 seconds. Each backend reproduced all 288 distinct RGB hashes and its own MP4 SHA-256 across both runs on this platform. ## Quality decision

The primary review artifact is the full-speed Godot MP4. Compare the paired MP4 at normal speed and step through frames 32–80, 130–148, 169–210 and 211–260. Check for a moving sole during stance, fingers crossing or detaching, elbows hiding the face, a crease that reads as a cut, and whether the proud response lands after the reprimand. The clip is a silent acting test. Grips are stylized, and close framing during the unfold emphasizes hands over feet.

Independent reviewer and scores are pending. Record movement/weight, eye/face acting, prop interaction, composition/continuity and timing/clarity separately on the 1–5 scale. The proposed target is at least 4 in each and zero blocking defects. The earlier motion-comic was unavailable in the checkout, so a blind comparison against it is also pending.
